# 希沃手机传图与课件遥控

登录或切换希沃账号后，插件自动启动独立 x86 `SeewoImBridge`，使用当前账号的 UID、Token 建立 IM 会话。已保存账号在插件初始化时也会启动。资料更新而凭证不变不会重启连接；退出、切换账号或插件关闭会取消旧队列、下载并终止旧辅助进程。连接超时为 45 秒，断线后间隔 5–60 秒重启辅助进程。日志中的“IM 已连接”仅在 SDK connected 回调后出现。

## 插图行为

- 未播放 EN 课件：调用宿主 `ICanvasInkService.InsertImageFromFileAsync`，插入完成导入时的 CE 当前屏幕批注/白板，复用依赖文件保存、压缩、选择和撤销。
- 正在播放 EN 课件：以 `insert-image` 请求送入 WebEasiNote 当前页，等待 `image-inserted` 完成回执。图片按比例居中并可交互选择、移动、缩放、旋转和删除。Web 临时元素跨页保留，但关闭/切换课件后清除，不保存到 ENBX；目前没有 Web 撤销栈。
- 路由以下载完成、准备插入时的放映状态为准。Web 解码期间切页/切换文档会失败，不能转而插到 CE。结束放映、请求取消和 30 秒超时会取消未完成的 Web 解码。
- CE 一旦开始 SDK 导入就不能中断；切页时按宿主接口插入完成时的当前画布。取消阻止排队任务及后续插入，但不删除已经插入的图片。

支持旧协议 301/302（1–9 张及空间检查）、303/304（下载 ZIP、取指定图片、完成后回执）、305 取消。支持照片列表 501/503、502 取消、504 启动回应、505/506 退出、531/532 按 ID 插入及回应。照片列表到达后直接插入，以满足手机发送后进入画板的行为；同一照片 ID 已成功插入后不因后续 501/531 重复插入。这是本插件的接入行为，未声称复现官方照片展示 UI。

图片下载不发送账号 Cookie 或 Token，仅允许公网 HTTPS/443，每次跳转重新校验，DNS 解析后仅连接公网地址。单个文件和 ZIP 指定条目的上限为 50 MiB，ZIP 最多 100 条目，不按压缩包路径解压，图片名不允许路径分隔符；仅提取唯一匹配条目到生成的本地路径。插入前通过 WPF 解码验证，限制为 4000 万像素，并转换为 PNG。支持 PNG/JPEG/BMP/GIF/TIFF/ICO；WebP 是否能解码依赖本机 WIC codec，失败时回应插入失败。临时文件在单项操作结束后清理。

## 手机控制 EN 放映

放映开始后发布 103 课件状态、202 放映信息及 207 当前页；支持 101/102 查询正在播放的课件、201/202 和 2011/2022 确认已有放映，以及 204 上一步、205 下一步。消息 body 中的 `id` 必须匹配当前课件；云课件使用真实 CID 和版本，本地 ENBX 使用本次放映的临时 ID。Web 文档加载通知附带完整 slideIds，207 使用实际 slideId 和从零开始的索引。未打开的课件请求返回 state=4，不自动下载或打开。

上一步/下一步复用宿主现有 Web 导航：优先执行页内动画，再翻页；等待导航提交后更新宿主页码和 CE 批注分页。遥控队列独立于图片下载队列，按顺序处理连续点击，并按传输 messageId 去重。排队命令绑定收到时的放映会话，关闭/替换课件及退出账号会取消或丢弃旧命令。放映结束发送 103/state=-1 撤回课件。

本次仅实现正在播放课件的前后步进。206 缩略图指定页跳转、203 手机结束放映、从手机打开尚未播放课件均未接入。动画 ID 暂回报空字符串，未实现桌面动画逐步状态的双向同步。手机界面是否接受本地临时 ID、是否需要更多进入遥控界面的消息，需真机验证；优先用登录账号下的同一云课件联调。

## 构建与部署

需要 Windows、.NET 10 SDK、本机安装的希沃白板 5 IMWrapper。默认构建引用 `EasiNote5_5.2.4.10148/Main`；其他位置可传 MSBuild 属性 `SeewoInstallDirectory`。主项目构建会先构建辅助进程，将其四个产物复制到插件的 `SeewoImBridge/` 并打包，不分发官方组件。

```powershell
pnpm --dir ../WebEasiNote build
dotnet build ICC.CE.ENBX.csproj -c Release
dotnet run --project tests/MobileImages/MobileImages.csproj -c Release
python tools/SeewoImBridge/smoke.py
```

部署需要支持新文件插图接口的 ICC-CE 宿主、本机希沃白板 5，以及 **x86 .NET 10 运行时**。插件仍可在旧宿主播放课件，但 CE 收图会失败并提示更新；使用反射探测新接口，不将新 SDK 方法作为必需加载依赖。IM 官方组件从安装目录加载，运行时默认扫描 `Program Files (x86)/Seewo/EasiNote5/EasiNote5_*/Main`；也可用 `ICC_CE_SEEWO_SDK` 指定 Main 目录。持久设备 ID 存在插件配置目录 `seewo-device-id`，会话 en5Id 为插件实例随机 GUID；凭证只经重定向 stdin 传递，不放入命令行或日志。父进程丢弃 native stderr，固定诊断消息可在宿主日志搜索 `[SeewoMobile]`。

## 验证边界

重复插图修复：501 与 503 可能携带相同照片，503 启动回应不应清空已插入照片 ID，也不应取消正在执行的同批次插入。现在保留成功记录，后续 531 只返回完成状态；退出/取消时清理。旧版 303 在当前批次内按地址和图片名重放回执，不重复导入。已新增对应消息顺序的回归检查。

CE 图片布局修复：原实现只切换套索工具，没有显示鼠标模式下隐藏的画布，且依赖隐藏元素的 Loaded 事件进行缩放。宿主现改为在添加图片前按解码尺寸计算最大 70% 画布的大小并居中，绑定交互与撤销后显示批注画布、退出鼠标穿透。该修复需更新宿主，单独更新插件无效。此前留在 CE 图层的原尺寸图片可能在进入 EN 批注时才显示，应在重试前清除这类旧图片；新插入图片不再延迟到 Loaded 才缩放。Web 图片的大小不会由此次宿主布局逻辑修改，插件日志新增 CE/Web 插图目标以便区分图层。

修复记录：宿主通过 `AssemblyLoadContext.LoadFromStream` 加载插件，插件程序集 `Location` 为空。辅助程序路径必须使用宿主注入的 `PluginFolder`，不能从程序集位置推导。修复前的运行日志仅出现“手机传图会话停止”，实际未启动 IM。现已改用插件安装目录，并补充辅助程序启动、异常类型/HRESULT 及断连 code 诊断，不记录凭证。安装目录中的辅助程序只读 probe 已通过。

2026-10-23 已通过插件构建、Web 构建、协议/回执/取消/来源匹配/ZIP 边界测试、已有云加载测试及辅助程序离线 smoke。只读 `--probe` 实际加载了 `IMWrapper.dll`、`ijwhost.dll`、四个 `rtmq_*` 模块，未提交 connect。`GetIMSdkVersion` 实际返回空字符串，不能用此结果断言 SDK 版本。

用户已在实际使用中反馈手机能够找到电脑并传图，CE/Web 已进入插图流程，随后修复了去重和 CE 显示问题。上述用户反馈不代表全部设备与账号的兼容验证。当前 904 在 connected/902 后发送是互通策略，未证明与官方发送时机一致。

手机遥控新增协议测试已覆盖课件列表、真实课件标识、索引、目标不匹配、重复消息、连续点击、进入放映回执、关闭/替换及取消；连同图片检查共 55 项通过。Web 云加载测试验证未加载页面也会发布完整 slideIds，并保留原有正文提交/迟到取消检查。尚未完成手机实际点按前后步进的端到端验证。

实际联调时更新宿主并安装新插件，登录同一账号，检查日志是否出现“IM 已连接”，然后从手机选择此电脑发送图片；分别验证 CE 批注、CE 白板、EN 放映、切页、取消及退出账号。若手机找不到设备，先核对账号凭证、运行时和官方依赖，再继续追踪发现协议，不能据离线测试宣称手机兼容已通过。
